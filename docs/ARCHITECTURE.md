# 架构：能力与环境分开，模型与执行分开

## 一张职责表

| 层 | 输入 → 输出 | 不应承担的责任 |
|---|---|---|
| 自然语言理解 | 用户文字、已发布能力 → Skill/Flow＋显式参数 | 不点击、不授权、不凭空增加技能 |
| Skill / Flow契约 | 参数、前后置条件、顺序与目标 | 不硬编码手机型号、屏幕坐标和控件序号 |
| 校验与编译 | 结构化调用 → 可检查计划或拒绝 | 不裁剪非法参数，不把部分意图当完整任务 |
| 环境Binding | App版本、页面和控件线索 → 当前可定位候选 | 不等于Skill语义，不携带别端执行批准 |
| Accessibility观察 | 当前Android窗口 → 结构化UI Tree与状态 | 不把旧节点缓存当当前事实 |
| Resolver | 当前Tree＋目标线索 → 唯一正确节点或明确缺失／歧义 | 不随机选相似Slider或按钮 |
| Runtime | 已授权计划＋当前节点 → 受限操作 | 不让GPT直接发输入，不无限重试 |
| Verifier / 回执 | 再观察＋前后置条件 → 真实终态与审计 | 不把发送成功、导入成功当任务成功 |

## 业务实体与宿主设备

`bedroom_light`是被控制的业务对象；Android手机／模拟器是承载App的宿主。二者不能混在`args.device`中。

```json
{
  "skill": "SetBrightness",
  "args": {"device": "bedroom_light", "percent": 80}
}
```

此对象只是说明性语义调用，不是授权文件或完整可执行Flow。实际还要经过本机批准、当前环境、参数与任务权限检查。

## 同App跨设备复用的核心

保留Skill语义和参数，用目标设备的当前UI重新定位。不将三星手机录下来的固定x/y直接搬到平板。

需要分别证明：两端环境一致、参数泛化、动态定位、实际状态核验、禁止副作用与失败回执。正确导入文件并不等于这几个问题全部通过。

## 当前源码边界

Android执行器与实验App在`android/`；宿主产品链路在`host/`；模型桥在`model-gateway/`。参考模块保留研究时的制品／依赖校验，不能为了让克隆版运行而绕开这些检查。

原始device evidence、审批、数据备份没有公开，因此本仓库能直接复现的基础目标是源码检查、纯逻辑测试和Android构建。完整模型端到端需要另行配置和授权。版本状态见[STATUS](STATUS.md)。
