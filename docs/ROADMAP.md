# 下一步：先稳定现有链路，再扩大环境范围

## 最近优先级

1. **完成当前原生资格。** 原四步Flow、原初态、原八秒和完整FINAL不变，取得正常与异常Android回执、pending／worker收口及实际计数证据。
2. **完成有限图形对照。** 原生关口成立后，同候选比较host/software后端；保留未运行、失败与恢复信息，不刷通过。
3. **统一候选再做双端确认。** 真机与模拟器使用同版本、同Skill／Flow、同入口与评分，分别报告同设备和跨设备结果。
4. **让部署真正可复现。** 逐项外置路径配置和依赖来源；保留严格校验，不通过删除守卫换取「可用」。

## 后续研究

| 方向 | 问题 | 应取得的证据 |
|---|---|---|
| UI变化 | 同App控件、入口或层级变化后能否复用原语义 | 单因素UI变体、自动重新绑定、独立状态核验 |
| 页面记忆 | 复用已验证记忆是否有收益 | 匹配初态下的首次／复用模型调用、动作与延迟比较 |
| 真实App | 能否减少复杂配置流程的重复培训 | 明确授权、代表任务、业务副作用与用户成本评估 |
| 使用体验 | 普通用户是否知道开始、结束、成功和失败 | 学习／保存／导入／调用全链路用户测试 |

## 每一轮的底线

冻结实现和测试条件；错误对象操作与误报成功独立统计；不能观察到就写UNKNOWN／UNCONFIRMED；任何修复保留修改前失败并建立新批次。次数、时间、取消和恢复都必须可审计。

计划是研究目标，不是已完成清单。当前真实状态见[STATUS](STATUS.md)。
